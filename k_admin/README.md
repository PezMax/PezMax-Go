# KAdmin

KAdmin 是一个前后端分离的后台管理项目。后端复用 [GoAdmin](https://github.com/GoAdminGroup/go-admin) 的公共组件，并在 `internal/kadmin` 中提供独立的应用接口；前端基于 [Vben Admin](https://github.com/vbenjs/vue-vben-admin) 的 Vue 3 与 Ant Design Vue 技术栈开发。

> 本项目是独立维护的二次开发项目，不是 GoAdminGroup 或 Vben 团队的官方发行版，也不代表上述项目对 KAdmin 的认可或背书。

## 当前能力

- JWT 登录、刷新令牌、退出登录和 Redis 令牌状态管理
- 服务端一次性图片验证码、Redis 登录失败锁定、IP 白名单和管理员解锁
- 用户管理、状态管理、密码重置、头像上传、用户导入，以及部门与职位分配
- 部门、职位（角色）、菜单、页面权限、按钮标识及用户授权管理
- 数据库驱动的动态菜单、组件映射和前端权限路由
- 字典类型与字典数据管理
- 系统配置管理
- 站内通知：数据库持久化的消息缓存，顶部铃铛未读提醒、已读/删除管理、通知中心页与系统事件自动推送
- 关键业务变更审计、敏感字段脱敏和 Redis 防重复提交
- Cron 定时任务、运行时暂停/恢复、立即执行与执行日志
- 可启停的系统监控、CPU/内存占用、服务器信息与运行时间
- 可启停的接口负载采样，按路由、方法或状态码查看请求量、QPS、错误率及耗时排行
- 代码生成器：PostgreSQL 表导入、字段识别与类型映射，一键生成前后端分页 CRUD（Model/Repository/Handler/路由、API 客户端、列表与表单页面、权限与菜单），支持预览、ZIP 下载与带冲突保护的落盘写入
- 自动生成的 Swagger API 文档与在线调试界面
- PostgreSQL 数据存储、Redis 鉴权状态存储
- 可选的 MinIO 对象存储和 Adminer 数据库管理工具
- 保留 GoAdmin 原有后台入口，供兼容和公共能力复用

## 技术栈

| 层级 | 技术 |
| --- | --- |
| 后端 | Go、Gin、GoAdmin 公共组件 |
| 前端 | Vue 3、Vben Admin、Ant Design Vue、TypeScript、Vite |
| 数据库 | PostgreSQL |
| 鉴权状态 | Redis |
| 可选存储 | MinIO |
| 本地依赖 | Docker Compose |

## 项目结构

```text
.
├─ admin-web/          # 独立 Vue 前端，主要应用位于 apps/web-antd
├─ internal/kadmin/    # KAdmin 应用后端，统一挂载在 /api
│  ├─ bootstrap/       # 权限和菜单种子定义
│  ├─ generated/       # 代码生成器输出（由生成器维护，勿手工修改）
│  ├─ modules/codegen/ # 代码生成器：表导入、类型映射、模板渲染与安全落盘
│  ├─ modules/files/   # 文件业务的完整 HTTP、服务和仓储链路
│  ├─ modules/jobs/    # 定时任务、内置处理器与执行日志
│  ├─ modules/loadrank/ # 接口负载采样、聚合与排行查询
│  ├─ modules/monitor/ # 可启停的系统指标采样与监控接口
│  ├─ modules/notifications/ # 站内通知：数据库消息缓存、已读与清理
│  ├─ platform/storage/ # 本地与 MinIO 对象存储实现
│  └─ transport/httpx/ # HTTP 响应和中间件基础能力
├─ adapter/            # GoAdmin Web 框架适配器
├─ engine/             # GoAdmin 核心引擎
├─ modules/            # GoAdmin 公共模块
├─ plugins/            # GoAdmin 公共插件
├─ template/           # GoAdmin 原后台模板
├─ data/migrations/    # PostgreSQL 历史迁移记录（仅追溯，权威种子见 tests/data）
├─ tests/data/         # PostgreSQL 初始化种子（admin_pg.sql，全新安装自动导入）
├─ main.go             # KAdmin 后端入口
└─ docker-compose.yml  # PostgreSQL、Redis、MinIO、Adminer
```

项目边界：

- GoAdmin 原后台保留在 `/admin`，不作为新页面的主要开发入口。
- 新的后端接口集中维护在 `internal/kadmin`，默认前缀为 `/api`；新业务优先在 `internal/kadmin/modules` 下按业务域聚合。
- 新的后台页面集中维护在 `admin-web`，沿用 Vben Admin 的组件和工程约定。

## 本地开发

### 环境要求

- Go 1.22.10 或更高版本
- Node.js 22.18+ 或 24+
- pnpm 11+
- Docker 与 Docker Compose

### 1. 启动依赖服务

项目的本地默认值已经与 `docker-compose.yml` 对齐，可以直接启动 PostgreSQL 和 Redis：

```powershell
docker compose up -d postgres redis
```

根目录 `.env` 同时供 Docker Compose 与本地 Go 后端使用，可从模板创建：

```powershell
Copy-Item .env.example .env
```

`go run .` 会自动加载根目录 `.env`，但不会覆盖已由操作系统或启动命令注入的环境变量。未创建 `.env` 时继续使用代码和 Docker Compose 中的本地默认值；生产环境必须显式替换数据库密码、Redis 密码、`KADMIN_JWT_SECRET` 等敏感配置。

### 2. 启动后端

```powershell
go run .
```

默认地址：

- 原 GoAdmin 后台：`http://127.0.0.1:9033/admin`
- KAdmin API：`http://127.0.0.1:9033/api`
- Swagger 文档：`http://127.0.0.1:9033/swagger/index.html`
- 根地址：`http://127.0.0.1:9033/`，会跳转到 `/admin`

Swagger 默认在调试模式下启用，可通过进程环境变量显式控制：

```powershell
$env:KADMIN_SWAGGER_ENABLED = 'true'
go run .
```

生产环境建议设置 `KADMIN_SWAGGER_ENABLED=false`。修改接口注释后，在项目根目录重新生成文档：

```powershell
go generate .
```

接口注释集中维护在 `internal/kadmin/swagger_operations.go`。生成文件位于 `internal/kadmin/docs`，包含可供 Swagger UI 使用的 Go、JSON 和 YAML 文档。

首次创建 PostgreSQL volume 时，Docker Compose 会自动导入 `tests/data/admin_pg.sql`，一次性获得完整表结构与初始数据（账号、角色、菜单、权限、字典与站点配置）。

已有 volume 不会重复执行初始化脚本；后端每次启动都会通过各模块的 `EnsureSchema` 幂等补齐缺失的表与索引，权限与菜单种子也会自动同步，无需手工执行任何 SQL。`data/migrations` 目录仅保留历史迁移记录（仅 PostgreSQL 方言）供追溯，权威种子与启动迁移已覆盖全部结构变更。

### 3. 启动前端

```powershell
Set-Location admin-web
corepack enable
pnpm install
pnpm dev
```

访问 `http://127.0.0.1:5666`。开发服务器会把 `/api` 请求代理到 `http://127.0.0.1:9033`。

初始化数据中的本地账号为 `admin` / `admin`，仅用于本地开发；首次登录后应立即修改密码。

### 4. 代码生成（可选）

登录后台后进入「KAdmin 管理 → 代码生成」：

1. 「导入表」选择一张 PostgreSQL 业务表，自动识别字段并推导模块名、类名与路由前缀；
2. 在独立配置页调整字段标签、控件类型及列表/查询/新增/修改/必填标记后保存；
3. 「预览」查看生成内容，「下载」导出 ZIP；「生成到项目」会把文件写入：

   - 后端：`internal/kadmin/generated/<module>/` 及共享注册表 `internal/kadmin/generated/registry.go`
   - 前端：`admin-web/apps/web-antd/src/api/kadmin/generated/` 与 `src/views/kadmin/generated/`

4. 重启后端以编译生成的路由、权限与菜单（写入数据库，启动时幂等同步）；前端开发服务器通过动态组件解析即时加载生成页面，无需重启。

带 `Code generated by kadmin codegen` 标记的文件重复生成时会被直接覆盖；没有标记的手工文件默认拒绝覆盖，需显式确认。生成的路由自动接入请求日志、业务审计、幂等防护与接口负载排行。

## 可选服务

启动 MinIO：

```powershell
docker compose --profile storage up -d minio minio-init
```

启动 Adminer：

```powershell
docker compose --profile tools up -d adminer
```

端口、默认账号和数据重置方式见 [DOCKER_LOCAL.md](./DOCKER_LOCAL.md)。
